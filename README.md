# KanAh！

KanAh！是独立的 Android TV 应用，提供直播、流媒体与音乐。电视安装后显示为「看啊」，语音启动识别待实机验证。原名 Live（实况），曾在 Maci 的 Android TV 目录维护，于 2026-11-16 拆分。当前候选使用 Android 应用 ID `com.siaovon.kanah`，此前的电视安装曾使用 `com.siaovon.khub` 和 `com.live.tv`。

当前能力仍是下面列出的媒体功能，不代表已完成 AI Agent 接入。

面向 Android 电视的直播、影视和音乐播放器。包名为
`com.siaovon.kanah`，最低支持 Android 8.0（API 26）；当前构建主要面向 ARM 电视。

## 功能

- **直播**：央视网页播放与自定义 IPTV
  播单，标题、暂停放大和横向频道选择采用点播播放器的同一套样式，频道条与暂停标题保持透明背景。直播画面上确认键切换播放／暂停，上下键直接换台；左右键呼出频道选择，继续左右预览、确认切换、返回取消。暂停时标题居中，播放失败时确认键仍用于重试。
- **导航**：应用内各页面及资源库弹窗均可用菜单键呼出侧栏；侧栏按“直播／流媒体／
  桌面模式／设置”排列并整体垂直居中，不显示时间。关闭侧栏后回到原焦点；直播打开
  横向频道列表，流媒体进入影视资源库，桌面模式用一个控件开启/关闭并请求系统默认
  桌面，设置直接打开电视系统设置。浏览流媒体、详情和应用设置时静音保留直播会话，返回直播恢复声音，并保留手动暂停状态；开始点播或离开应用时释放直播播放器。
- **影视（统一播放器）**：流媒体不再另开播放页，而是在同一播放器壳内预览和播放。当前资源有历史进度时先显示上次退出时缓存的视频帧，同时后台在保存位置准备播放器；无进度时不再请求海报，而是后台准备第一集开头媒体并显示视频首帧。右侧相邻资源会预加载第一集开头播放器，暂停时向右切换可直接接管；影视主题色取自实际视频帧。资源名在无播放画面时呈暂停态，确认键直接开始播放。底部固定三行：资源名（短按播放／暂停、长按全屏搜索，右侧依次为复用音乐播放页样式的实心播放／暂停图标和加载／错误状态）、播放控制（倍速／音轨／字幕）＋线路来源、单行选集条。播放前倍速／音轨／字幕显示为禁用，线路可正常切换；无播放资源时左右键切换目录资源，有画面且暂停时同样切资源，正在播放时左右键快进／快退；焦点在选集或控制行时左右操作该控件。缓存不再有独立模式：聚焦选集长按确认键缓存或删除该集，下载中左侧显示主题色环形进度，完成后显示绿色圆形勾选；每集文字本身按播放进度以主题色填充，不再在文字下方单独绘制进度条。播放中控制层自动隐藏后，再次按键呼出时焦点回到当前播放的选集。返回直接退出到直播；搜索浮层打开时先关搜索。支持 TVBox type 1 / MacCMS JSON 来源及直接 HLS / MP4。
- **播放器**：统一播放器沿用底部资源名、播放控制和单行选集；倍速／音轨／字幕在预览时可见但禁用，开始播放后可用；线路／来源控件位于字幕右侧。
- **缓存**：按资源查看已缓存集数及继续播放；聚焦选集长按确认缓存或删除该集，删除前确认，下载中的任务会停止；来源失效后仍可删除其本地缓存。
- **音乐**：电视内搜索与播放、封面与歌词显示，以及本地缓存；搜索结果中的歌曲与影片共用全屏海报位，聚焦歌曲时底部显示歌名和歌手。
- **桌面模式与系统设置**：桌面模式默认关闭，侧栏控件开启后请求系统选择器将
  K站设为默认桌面，原有应用启动入口保留；侧栏“设置”直接打开电视系统设置。

影视、音乐及直播依赖外部服务和用户配置的来源，可能受接口变化、网络、地区或资源失效影响。XML、完整

## 开发

构建需要 JDK 17 或 21、Android SDK Platform 36、Build Tools 35.0.0
和网络连接。用 Android Studio 的 SDK Manager 安装 SDK 并接受许可，设置
`ANDROID_HOME` 或在本地 `local.properties` 配置 `sdk.dir`，然后执行：

```sh
git clone https://github.com/intpfx/KanAh.git
cd KanAh
./gradlew :app:assembleDebug
```

Windows 用 `gradlew.bat :app:assembleDebug`。仓库自带 Gradle 8.13 Wrapper，
首次运行会校验并下载 Gradle，再从公开 Maven 仓库解析依赖。Cronet 使用 Google Maven
的 `org.chromium.net:cronet-embedded:143.7445.0`，并由 Gradle 拉取它声明的依赖。

Debug APK 输出为 `app/build/outputs/apk/debug/app-debug.apk`。
Android 单元测试和 lint 可用 `./gradlew :app:testDebugUnitTest :app:lintDebug`。
另外可用 `sh tests/run.sh` 运行 Java 和 JavaScript 行为测试，其中 JavaScript
媒体片段测试需要 Node.js、FFmpeg 和 ffprobe。家庭候选签名及 APK 核验见
[家庭自用发布](docs/FAMILY-RELEASE.md)。

## 连接与使用

电视侧不提供手机遥控或网页入口。流媒体与播放共用一个原生播放器：无播放进度时
直接准备开头媒体并显示视频首帧，有进度时显示暂停的最新视频帧；底部三行依次为
资源名、播放控制（倍速／音轨／字幕与线路来源）、单行选集。短按资源名播放／暂停，
长按打开全屏搜索；搜索结果中的
影片切换后立即播放，歌曲进入音乐播放。左右键在画面焦点下按播放/暂停状态切换资源
或快进快退；“桌面模式”在侧栏开启/关闭默认桌面，“设置”直接打开电视系统设置。
内置代理已整体移除，所有网络请求直连；已移除功能遗留的本地数据会在应用启动时清理一次。
原先的触控遥控、多人手柄、网站浏览、HTTPS 证书、PWA 主屏幕和离线壳
均已随 Web 面板移除；旧面板地址和二维码不再可用，LAN 端口与扫描入口一并删除。

Web 面板移除不改变电视待机限制：Redmi 实测待机策略会强停
Live，电源键唤醒后需重新打开应用，约 6 秒恢复原频道。当前没有已验证的通用网络唤醒功能，播放恢复逻辑也不能阻止系统强停。
2026-11-07 对 Android 14 电视的诊断确认，切到其他应用再回桌面后应用会进入
cached 状态并被系统冻结；该结论现在只影响直播恢复，不再涉及 Web 服务。
电视日志明确拒绝非系统应用的前台服务提升；后台保活仍待选择系统支持的方案并实机验证，
不修改全局冻结策略，也不将其视为待机或网络唤醒已实现。

## 从旧版迁移

迁移目标为 `com.siaovon.kanah`，默认从 `com.siaovon.khub` 迁移，也支持仍安装 `com.live.tv` 的电视。迁移工具只适用于由同一调试签名签署的旧版与新版。

- 由旧应用在自己的身份下读取 Android Keystore 加密的影视来源，迁移时由新应用的 Keystore 重新加密。保留来源 ID、修订和代次，使本地缓存和进度仍能匹配原资源。迁移不得记录来源地址和鉴权信息。
- 迁移直播配置、影视和音乐会话、观看进度、暂停快照及对应媒体缓存。影片缓存需同时核对分片、任务索引与 Media3 数据库，音乐缓存需核对曲目清单和文件。
- 写入新版前校验迁移包和目标状态，使用测试资料核对导入、重试与失败恢复。电视上验证新版可读配置、离线播放缓存并从原位置续播后，旧应用和数据仍保留，供用户确认。

工具入口为 [scripts/migrate-legacy-debug.sh](scripts/migrate-legacy-debug.sh)。先运行
`./gradlew :app:assembleDebugAndroidTest -PmigrationSource=com.siaovon.khub` 并单独保留产出的旧版辅助 APK，
再运行 `./gradlew :app:assembleDebug :app:assembleDebugAndroidTest` 生成新版和新版辅助 APK。
电视上保留旧应用，安装两个辅助 APK 和新版后，在首次打开新版前执行
`scripts/migrate-legacy-debug.sh <adb-device>`。若旧版为 `com.live.tv`，构建旧版辅助 APK 时将 `migrationSource` 设为该包名，并在执行脚本时将包名作为第二个参数。工具会暂时停止两个应用，媒体与配置在设备内传输，校验文件后导入，并验证完成缓存可由纯缓存数据源读取。目标已有对应资料时停止，失败暂存材料保留以供检查。两套辅助程序均在独立测试 APK 内。
