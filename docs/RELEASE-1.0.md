# 1.0 发布准备

本文件是发布门槛，不是发布公告。仓库整理、自动测试或 Debug 构建通过，不代表已签名、发布或完成真机验收。当前版本信息以 `app/build.gradle` 为准；升级版本号、创建标签和发布安装包须在候选通过验收后执行。

## 发布范围与当前候选

家庭设备沿用现有签名密钥，GitHub 标签发布使用独立签名。当前主线候选为 `1.0.0-rc1-recovery3` / 73；构建与核验方式见 [家庭自用发布](FAMILY-RELEASE.md)。开源仓库中的 KanAh！自有源码采用 MIT 许可证。公开分发 APK 和商店准备仍按独立流程处理，须保留原有第三方许可声明。

当前 Redmi 安装的双架构 Debug 开发包已于 2026-10-25 与主线构建逐字节核对一致，功能和验证范围见 [主线同步记录](main-sync-20261025.md)。这不等于签名 Release 发布验收。[2026-10-22 实机记录](redmi-stability-20261022.md)属于更早的 ARMv7 候选，覆盖 15 分 3 秒连播、部分频道切换、返回前台与冷启动，不能替代当前新功能的验收。

## 候选范围

保留直播、电视内影视与音乐统一搜索、原生流媒体海报墙与选集、缓存下载与删除、全局侧栏、可选桌面模式，以及播放器线路／来源菜单中的影视来源入口。内置代理模块与 Maci 设置页已整体移除，侧栏设置直接打开系统设置。2026-11-10 按用户决定移除 Web 面板、局域网二维码、HTTP／HTTPS 服务、多人手柄、网站浏览及 HTTPS/PWA 主屏幕路径，不再列入 1.0 范围。应用内浏览时静音保留直播，开始点播或离开应用时释放直播。播放器使用当前设备的系统无衬线粗体；艺术字体、海报标题自动提取与本地大模型不进入 1.0。

- [ ] 确定 1.0 功能边界和已知限制；确认搜索详情、来源选择及缓存恢复没有阻断性问题。
- [ ] 在最终候选提交上执行下列检查，记录提交号、运行环境和结果；不能沿用旧提交的测试数字。
- [ ] 配置正式发布签名，确认密钥安全备份及后续更新可持续使用。Gradle 已支持环境变量签名；家庭候选沿用现有密钥并关闭调试，密钥备份尚需用户确认。
- [ ] 核对已安装版本的签名及升级兼容性；不同签名不能直接覆盖升级，发布前确认频道、配置、缓存和继续播放数据的迁移安排。
- [ ] 验收通过后设置 `versionName` / 递增 `versionCode`，构建并检查正式 APK 的包名、签名、版本、ABI、调试开关及内容。
- [ ] 核查 APK 所含复用代码、素材和全部第三方依赖的分发权利，落实必要通知及对应源码交付安排。
- [ ] 检查发布包和仓库不含私钥、证书密码、订阅令牌、设备备份、调试截图或研究模型。
- [ ] 经发布授权后创建版本标签、更新说明及安装包校验和，并核对实际下载产物与候选一致。

## 候选验证命令

在仓库根目录、已配置 JDK / Android SDK 的环境执行；macOS PATH 设置见 [开发环境](../AGENTS.md#开发与验证)：

```sh
./gradlew :app:assembleDebug :app:lintDebug :app:testDebugUnitTest
./tests/run.sh
```

正式签名配置完成后还需构建和检查 Release 产物。组件或单元测试不能替代媒体播放、缓存、系统手势或电视生命周期验证。

- [ ] 标题播放/暂停过渡、资源名右侧的实心播放/暂停图标（复用音乐播放页样式）与状态（图标与标题视觉统一、无左上角旧浮层）、流体进度、缓冲指示、选集文字主题色进度、呼出焦点回到当前选集及倍速/音轨/字幕焦点；确认实体遥控器操作一致。

- [ ] 连续长时间播放、应用切换、进程重启与断电恢复；记录至少目标 ARM 设备上的实际结果和未覆盖的系统版本。

## 已知边界

**待机与网络唤醒**：Redmi 实测待机时由系统强停 Live；电源键唤醒后仍需手动重新打开应用，约 6 秒恢复原频道。播放恢复修复不能阻止系统强停。没有完成标准网络唤醒的有效验证，当前不能宣称支持待机保活或自动续播。

**外部来源**：影视、音乐和央视网页接口可能变动或间歇性失败，网络、地区或来源失效也会影响可达性。发布说明须明确支持范围和失败恢复方式，不承诺来源永久可用。

**局域网面板已移除**：本地 CA、HTTPS 证书、二维码与主屏幕安装路径不再维护；旧面板地址和 LAN 端口不可用。不得恢复这些入口或把旧证书作为发布配置。

**兼容性**：最低 API 声明不等于覆盖全部电视。ARMv7 / ARM64 原生依赖、系统字体映射、WebView 版本及厂商电源策略需要按目标设备验证。
